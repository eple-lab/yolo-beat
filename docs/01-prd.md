# 01. PRD (제품 요구사항)

> YOLO-Beat가 무엇이고, 왜 이걸 만들게 됐고, 어디까지가 첫 버전인지 적은 문서예요.
> 작성: 2026-11-14 (개발 기간 2026-11-10 ~ 11-12의 대화를 바탕으로 정리)

## 1. 한 줄 요약

**노트북 웹캠 앞에서 손을 휘둘러 화면의 드럼 패드를 치면 드럼 소리가 나는 데스크톱 앱.**
Ultralytics YOLO의 Pose 모델로 손목을 찾고, 손목이 패드에 들어가는 순간 numpy로 합성한 드럼 소리를 낸다.

## 2. 배경: 아이디어를 고른 과정

처음 요청은 "YOLO로 노트북 웹캠에 적용하는 서비스를 만들고 싶다. 어떤 서비스를 만들 수 있을까?"였다.
바로 정하지 않고 후보를 세 번 좁혔다.

### 2-1. 1차 후보: 웹캠으로 할 수 있는 서비스 6개

YOLO가 할 수 있는 일(Detect, Pose, Segment, Track, Classify)을 기준으로 후보를 냈다.

| # | 후보 | 쓰는 기능 | 장점 | 어려운 점 |
|---|---|---|---|---|
| 1 | 공부 집중 타이머 (자리 비움·폰 감지) | Detect + Track | 학습 없이 바로 동작 | 작은 폰은 놓침 → "N초 연속 감지" 같은 오탐 방지 로직 필요 |
| 2 | 거북목·자세 교정 알리미 | Pose | 실용적 | 정면 웹캠은 앞뒤 깊이를 모름 → 대리 지표 필요 |
| 3 | 홈트 횟수 카운터 | Pose | 재미 | 전신이 화면에 들어와야 함 |
| 4 | 자리 비움 중 침입 알림 | Detect | 간단 | 외부 알림 시 보안 점검 필요 |
| 5 | 손 제스처로 PC 조작 | 손 키포인트 | 학습 경험 | COCO에 손 클래스 없음 → 커스텀 학습 필요 |
| 6 | 화상회의 배경 처리 | Segment | 시각 효과 | 가상 카메라 연동이 YOLO 밖 작업 |

이때 추천은 1+2를 묶은 "책상 앞 코치"였다.

### 2-2. 2차: 요가 자세 가이드 (반려)

eple이 제안: "화면에 요가 동작(난이도 1~10)을 띄우고, 동작이 맞는지 판정해서 어떻게 고쳐야 하는지 가이드해 주는 서비스."

검토 결과 **가능은 하지만 무겁다**고 정리했다.

| 검토 항목 | 내용 |
|---|---|
| 판정 방법 | 관절 17점으로 각도를 계산하고, 동작마다 목표 각도와 허용 오차를 정의해서 비교 |
| 2D 한계 | 웹캠은 깊이를 몰라서 같은 자세도 보는 방향에 따라 각도가 달라짐 → 동작마다 정면/측면 지정 필요 |
| 전신 촬영 | 노트북 웹캠은 화각이 좁아서 2.5~3m 떨어져야 함(추정) |
| 누운 자세 | COCO 학습 데이터는 대부분 서 있는 사람 → 정확도 저하 가능 |
| 화면을 못 봄 | 동작 중에는 화면을 보기 어려워 음성 피드백(TTS)이 거의 필수 |
| 난이도 1~10 | 동작 정의(목표 각도, 오차, 방향, 난이도)를 사람이 다 만들어야 함 → 가장 큰 비용 |
| 참고 이미지 | 인터넷 요가 사진은 저작권 문제 → 스틱맨으로 그려야 함 |

eple의 판단: **"그럼 별룬데. 간단하게 할 수 있으면서도 기발한 거 없을까?"**

### 2-3. 3차: 간단하면서 기발한 후보 5개

조건은 "사전학습 모델 그대로, 학습이나 데이터 정의 없이 하루 이틀 안에 동작하는 것"이었다.

| # | 후보 | 핵심 로직 | 난이도 |
|---|---|---|---|
| 1 | 어깨 너머 감시자 (사람 2명 이상이면 화면 가리기) | person 수 세기 | ★☆☆☆☆ |
| 2 | 실루엣 통과 게임 | Segment 마스크와 구멍의 IoU | ★★☆☆☆ |
| 3 | 집안 보물찾기 타임어택 | COCO 물건 Detect | ★☆☆☆☆ |
| 4 | 허공 드로잉 | 손목 궤적 | ★☆☆☆☆ |
| 5 | **몸 악기** | Pose 손목 + 구역 충돌 + 소리 | ★★☆☆☆ |

eple이 **5번 몸 악기**를 골랐다("이거 좋아보여").

## 3. 목표

- 웹캠 하나로, 별도 장비 없이 손을 휘둘러 드럼을 치는 재미를 준다.
- GPU 없는 일반 노트북(CPU만)에서 실시간으로 동작한다.
- 학습 데이터 없이 사전학습 모델만 쓴다.
- 처음 하는 사람도 따라 만들 수 있게 과정을 문서로 남긴다(이 docs 폴더).

## 4. 사용자와 사용 장면

| 항목 | 내용 |
|---|---|
| 사용자 | 노트북을 가진 개인. 처음에는 개발자 본인(eple) |
| 장면 | 노트북 앞에 앉거나 기대 앉아서, 상반신과 양손이 화면에 들어오게 하고 손을 휘두른다 |
| 환경 | Windows 노트북, 내장 웹캠, 스피커 또는 이어폰 |

## 5. 기능 (첫 버전, 완료)

| ID | 기능 | 상태 |
|---|---|---|
| F1 | 웹캠 영상을 좌우 반전(거울)해서 보여 준다 | ✅ |
| F2 | YOLO Pose로 양손 손목을 찾아 점으로 표시한다 | ✅ |
| F3 | 화면 양쪽에 드럼 패드 6개를 그린다 (왼쪽 crash/hihat/snare, 오른쪽 ride/tom/kick, 가운데 비움) | ✅ |
| F4 | 손목이 패드에 **들어가는 순간** 1번만 소리를 낸다 (머물러도 다시 안 울림) | ✅ |
| F5 | 같은 패드는 120ms 안에 다시 울리지 않는다 (경계 떨림 방지) | ✅ |
| F6 | 손목 감지가 3프레임까지 끊겨도 다시 울리지 않는다 | ✅ |
| F7 | 드럼 소리 6개를 numpy로 합성한다 (샘플 파일 없음) | ✅ |
| F8 | 맞은 패드를 노랗게 깜빡이고, 터미널에 시간·패드·손·직전 타격 간격을 찍는다 | ✅ |
| F9 | 옵션: `--imgsz`, `--mute`, `--seconds` | ✅ |
| F10 | 손목 인식·FPS 확인 도구(`pose_preview`, `--bench N`) | ✅ |

## 6. 비기능 요구

| 항목 | 목표 | 실제 (측정) |
|---|---|---|
| 속도 | 악기로 쓸 수 있는 실시간 | 입력 크기 320에서 벤치마크 15~17.6 FPS, 실제 앱 화면 11~14 FPS |
| 지연 | 치는 순간과 소리 사이가 거슬리지 않게 | 추정 70~100ms (측정 안 함) |
| 하드웨어 | GPU 없이 | Intel i5-1035G7(10세대, 4코어), 내장 그래픽 |
| 설치 | 명령 몇 개로 | `uv sync` 하나, 모델은 첫 실행 때 자동 다운로드 |
| 테스트 | 웹캠·스피커 없이 핵심 로직 검사 | pytest 20개 |

## 7. 보안 (다루는 데이터와 위험)

| 항목 | 내용 |
|---|---|
| 다루는 데이터 | 웹캠 영상(얼굴과 방이 찍힘) |
| 저장 | **영상과 프레임을 디스크에 저장하지 않는다.** 메모리에서 추론하고 버린다 |
| 외부 전송 | 앱은 영상을 밖으로 보내지 않는다. 네트워크는 첫 실행 때 모델 다운로드(GitHub 릴리스)뿐 |
| 접근하는 사람 | 노트북 앞의 사용자 본인 |
| 예상 위험 | ① Ultralytics 라이브러리의 익명 사용 통계(settings의 `sync`, 끄는 것은 남은 일) ② 공개 저장소에 개인정보가 섞이는 것 → 커밋 전 검사로 막음 ([06-test-log.md](06-test-log.md)의 개인정보 검사) |
| 문서의 스크린샷 | 시험 화면에 얼굴이 나와서 저장소에 넣지 않았다 |

## 8. 범위 밖 (첫 버전에서 하지 않음)

- 손가락 단위 인식 (COCO 17점에는 손가락이 없음)
- "치는 동작" 판정 (지금은 들어가기만 하면 울림)
- 피아노 등 다른 악기, 녹음, 박자 맞추기 게임
- 웹 버전, 모바일
- 패드 배치 편집 화면

## 9. 성공 기준 (첫 버전)

| 기준 | 결과 |
|---|---|
| 6패드가 모두 실제로 울린다 | ✅ 실기 시험 1회차 75회 타격, 6패드 모두 맞음 |
| 가만히 있으면 잘못 울리지 않는다 | ✅ 스크린샷 기준, 손을 패드에 둔 채로는 다시 울리지 않음 |
| 소리가 드럼처럼 들린다 | ✅ eple이 들어 보고 "좋다" |
| 핵심 로직이 자동 테스트로 검증된다 | ✅ 20개 통과, 일부러 망가뜨린 버전도 잡음 |

## 10. 다음 기능 (남은 일)

| 순위 | 기능 | 방법 | 예상 시간 |
|---|---|---|---|
| 1 | **손끝 추정** | 팔꿈치→손목 방향으로 아래팔 길이의 약 0.7배를 연장한 점을 판정에 사용 | 30분~1시간 |
| 2 | **치는 동작 판정** | 진입 속도가 기준 이상일 때만 울림 + 이전 위치→지금 위치 선분이 패드를 지나는지 판정 + 속도에 따른 음량 | 약 1시간 + 기준값 튜닝 |
| 3 | Ctrl+C 종료 정리 | 정리 단계(카메라 해제) 중 Ctrl+C 무시 | 짧음 |
| 선택 | 익명 통계 끄기, 패드 배치 조정, FPS 개선(OpenVINO, YOLO26n-pose 비교) | | |

손끝을 정확히 잡는 다른 방법(손 전용 21점 모델 학습, MediaPipe Hands)은 **오래 걸려서 하지 않기로** 했다.
자세한 이유는 [07-decisions.md](07-decisions.md)의 D-16.
